# Go API — Architecture & Build Blueprint (generic)

> A blueprint for a **modular, maintainable, extensible, verifiable, regeneratable, vibe-mutatable,
> contract-oriented** Go API. **Go 1.26 + PostgreSQL 16.** Hexagonal architecture, DDD bounded
> contexts, **spec-first OpenAPI 3.1** (ogen) with strict conformance gating, **type-safe SQL**
> (sqlc), compiler-enforced typing reinforced by strict linting, statement coverage + mutation
> testing, strict golangci-lint, DB-level integrity, and a verified supply chain.

**This document is the source of truth for agents building and extending the app.** Numbered
restrictions are **gates**, not suggestions — a PR that violates one does not merge. Replace
placeholder names (`Resource`, `contextx`) with your domain; keep the structure.

---

## 0. The seven properties this architecture exists to guarantee

Every rule below serves one of these, and they reinforce each other:

- **Modular** — bounded contexts behind compiler-enforced `internal/` surfaces; hexagonal layers
  inside each. Nothing reaches across a boundary it shouldn't.
- **Maintainable** — one explicit way to do each thing; no hidden control flow, no ORM magic, no
  package-level mutable state.
- **Extensible** — ports & adapters mean new behavior is a new adapter or use case, not a rewrite.
  The "add a feature" recipe (§17) is the only motion you need.
- **Verifiable** — the compiler, the linters, the coverage + mutation gates, the contract
  conformance, and the architecture rules together make "is this correct?" a CI question, not a
  judgment call.
- **Regeneratable** — the API surface (ogen), and the data layer (sqlc) are generated from a single
  declared source, and the migrations (goose) are that source for the schema; you regenerate rather than hand-edit.
- **Vibe-mutatable** — *this is what the gates are for.* A dense net of types, generated contracts,
  fast tests, and exhaustiveness checks lets a human or an AI agent change the code confidently and
  fast: a wrong edit fails to compile, fails a linter, or fails a test, immediately and locally. The
  rigor is what makes loose, exploratory iteration *safe*.
- **Contract-oriented** — an OpenAPI 3.1 document is the source of truth for every boundary; it is
  conformance-gated, drift-checked, and every consumer is generated from it.

**Why Go is well-suited here, and the one honest tradeoff.** Go gives enforced static typing with no
gradual-typing escape hatch, a single static binary, excellent concurrency, and the strongest
practical supply-chain story of the backends. Its one weakness for *verifiability* is that it has **no
sum types, no real enums, no exhaustiveness, and `nil`/zero values are holes in the type system** —
the validatability Kotlin/Rust get from the language, Go must buy back with linting. §6 is how; with
those linters as blocking gates, the gap closes in practice.

## 1. Goals & non-negotiables

| Contract conformance | Strict OpenAPI linting (Redocly `recommended-strict` + vacuum + OWASP) **gates before codegen** (§9). |

| Error model | Idiomatic `(T, error)` with typed/sentinel errors; mapped to **RFC 9457 problem+json** at the edge (§10/§19.5). |
| Test coverage | Statement-coverage gate (100% on the pure domain), plus **mutation testing** (gremlins) on the core (§16). |
| Lint/style | Strict **golangci-lint v2** + `gofumpt`; zero issues is a gate (§15). |
| Architecture | Hexagonal + DDD bounded contexts; boundaries enforced by **`internal/`** (compile-time) + **depguard** (§2/§7). |
| Security | `gosec` + `govulncheck` in CI; CORS, security headers, rate limiting (§19). |
| Observability | Structured logs via stdlib **`log/slog`**; request IDs; `/healthz` (§19). |
| Background work | Postgres-backed queue (**River**) or goroutines; jobs are adapters driving use cases (§20). |
| Deployment | Single static binary in a distroless/scratch image; Postgres-only deps (§19). |
| Real-time (optional) | Server-authoritative state + an in-process WebSocket hub (§21). |

## 2. The dependency rule

Source dependencies point **inward only**: inbound adapters (ogen handlers, jobs, CLI, WS hub) →
application (use cases) → domain (entities, value objects, ports = interfaces); outbound adapters
(sqlc repos, gateways) implement the ports. The domain imports no `net/http`, no `pgx`, no generated
code. Wiring is explicit constructor injection at `cmd/<app>/main.go` — no container, no magic.

**Enforcement (compiler-level):** a context's internals live under `internal/`, so cross-context
reaches don't compile. **depguard** (a golangci-lint linter) covers the "domain must not import
transport/SQL" and "may use X's public surface but not Y" edges and fails CI on a violation.

---

## 3. Bounded contexts

A few deliberately decoupled contexts, each a package tree under `internal/`. Group by business
capability and ownership; separate read-mostly reference data from user-mutable transactional data,
and give pure computation/policy its own package (where typing, coverage, and mutation testing pay off
most). Cross-context references are an **anti-corruption boundary** — a plain identifier, never a DB
association across context lines. `internal/` is the compiler-enforced public surface; communicate by
value.

## 5. Runtime — no decision to make

One runtime: true multicore, no JIT-warmup tradeoff, no C-extension matrix, a single native binary.
The "framework-free domain" discipline other stacks keep for portability is simply good design here.
**Standing guard:** `go test -race` in CI — Go concurrency is easy to get subtly wrong, especially
around the realtime hub (§21).

## 6. Typing & validatability — buying back what the language lacks

The compiler is the type gate (not gradual — no untyped escape hatch). The work is closing three
holes so "verifiable" holds in practice.

**6.1 The boundary is generated and validated.** ogen generates request/response validation from the
spec (required, formats, ranges, `enum`, `oneOf` discriminated unions) and uses tri-state `Opt`/
`OptNil` wrappers (`Set`/`Null`/`Value`) — closing "can't tell unset from zero" at the API edge. sqlc
maps nullable columns to null-aware types and PG enums to Go typed constants.

**6.2 The interior holes — each plugged with a pattern + a gating linter:**

| Hole | Plug | Gating linter |
|---|---|---|
| `nil` | prefer value types; wrap real absence in `Opt[T]` | **NilAway** (module plugin) + `govet` nilness |
| zero vs "set" | unexported fields + constructors | **`exhaustruct`** (all fields initialized) |
| no enums/exhaustiveness | typed const enums | **`exhaustive`** (`//exhaustive:enforce`; no `default`) |
| no sum types | **sealed interface** (unexported marker method) | **`gochecksumtype`** (non-exhaustive switch fails CI) |

```go
type PaymentResult interface{ isPaymentResult() }
type Captured struct{ Ref string }
type Declined struct{ Reason DeclineReason }
type PendingReview struct{}
func (Captured) isPaymentResult()      {}
func (Declined) isPaymentResult()      {}
func (PendingReview) isPaymentResult() {}
// switch over the union is gochecksumtype-checked; review forbids `default` to dodge exhaustiveness.
```

It's a linter, not the compiler (config sets `default-signifies-exhaustive: false`); wired as blocking
gates, practical validatability is close. **Value objects** use unexported fields + a constructor
returning `(T, error)`; `exhaustruct` makes a half-built literal a lint error.

**6.3 The CI "type gate"** = `go build ./...` + `golangci-lint run` (with §6.2 linters) + `sqlc vet`
+ `squawk`.


`internal/` makes one context's internals unimportable from another; depguard covers the rest.

## 8. Database design & persistence

**8.1 Normalize; no JSONB (hard default).** Typed columns, lookup tables + FK, child tables, join
tables. Speed from **indexes** (btree on FKs/filter columns; composite; covering `INCLUDE`; partial),
not documents. Rare opaque third-party blob is the only exception, with an inline reason + sign-off.

**8.2 Integrity lives in the database.** Every "required" is `NOT NULL`; references are FKs; "one of"
is `CHECK`/PG `ENUM`; "unique" is a unique index; "exactly one of" is `CHECK (num_nonnulls(...) = 1)`.
No separate ORM-validation layer to drift from — sqlc reads the same schema.

**8.3 sqlc.** Write SQL; sqlc generates exact, compile-time-checked Go. **No ORM, no lazy loading →
the N+1 class is structurally absent.** A typo or missing column fails `sqlc generate` before
compilation. Repository adapters wrap the generated `Querier` and map rows ↔ domain so the domain
never sees a `pgtype`.

**8.4 Migration safety — goose + squawk.** `db/migrations/*.sql` are ordered, forward-only goose
migrations, embedded in the binary and applied by it at startup in one transaction each; sqlc reads
the same files as the schema. **`squawk` fails CI** on destructive, lock-taking or non-rerunnable
statements; every migration sets `lock_timeout` and `statement_timeout`, and a rule is silenced only
by a `squawk-ignore` comment on the statement, with its reason. Two-phase column drops and batched
backfills are hard rules.

## 9. OpenAPI conformance — strictness gates (before codegen)

Hold the authored contract to the strictest practical rulesets as a **blocking gate before codegen**:
**Redocly `recommended-strict`** (warnings→errors; plus `operation-operationId`,
`operation-4xx-response`, `security-defined`, `no-unused-components`, `spec-strict-refs`); **vacuum**
(Go binary, ~88 rules, OWASP built-in, `--min-score`); **Spectral** + the OWASP ruleset.

```
1. spec gate:   redocly lint && vacuum lint --fail-severity error && spectral lint
2. generate:    go generate ./...      (ogen)
3. drift check: git diff --exit-code internal/platform/api
4. compile:     go build ./...
```

Five independent layers of contract adherence: spec is provably standard-conformant → client is
provably derived → app provably matches the types → ogen validates every request at runtime.

## 10. Application layer — use cases return (T, error)

One function/struct per business action; the only entry point handlers and jobs call. Validate input,
orchestrate domain, return `(T, error)` with **typed/sentinel errors** mapped to RFC 9457 at the edge
(§19.5). No business logic in handlers; the domain method holds the rule and is unit-tested alone.

```go
func (uc ActivateResource) Handle(ctx context.Context, id ResourceID) (Resource, error) {
    r, err := uc.repo.ByID(ctx, id)
    if err != nil { return Resource{}, fmt.Errorf("load: %w", err) }
    if r == nil   { return Resource{}, ErrNotFound }
    activated := r.Activate(uc.clock())              // pure domain method
    return activated, uc.repo.Save(ctx, activated)
}
```

## 11. Design pattern catalogue

Ports & adapters (interfaces + constructor injection); Repository (sqlc-backed); Gateway (HTTP-client
adapter); Strategy (interface/func value); Value Object (unexported fields + constructor,
`exhaustruct`-guarded); Discriminated union (sealed interface + `gochecksumtype`); Use Case (struct
with `Handle`); State machine (typed enums + `exhaustive` switches); Error envelope (typed errors →
problem+json). The composition root is plain Go — "frozen after boot" because nothing mutates the
wiring after `main`.

---

## 12. External integrations

Each outbound integration is an adapter implementing a domain port, behind one interface. An
import/sync is an inbound adapter (CLI subcommand or River job): idempotent (upsert on a natural key),
stubbed in tests with `httptest` (**no live network in tests**), normalized at the boundary.

---

## 13. API + OpenAPI (spec-first)

The **OpenAPI 3.1 doc is hand-authored and is the source of truth.** ogen generates the typed
`Handler` interface, request/response types, a static router, and validation; you implement the
interface with thin handlers (authenticate → call use case → map result). **CI fails on drift**
(`go generate` + `git diff --exit-code`); consumers regenerate clients from the same spec. A single
mapper emits **RFC 9457 problem+json**. ogen is preferred for reflection-free JSON, real `oneOf`
unions, enum types, and tri-state wrappers; **oapi-codegen** is the alternative.

---

## 14. Performance & efficiency

Indexes do the work (btree/composite/covering/partial). HTTP caching (ETags) on read-mostly
endpoints. **N+1 structurally absent** with sqlc; belt-and-braces query-count assertion via pgx
tracing. Pagination everywhere (keyset preferred). `pgxpool` sized to concurrency; prepared statements
on. Explicit `SELECT` columns.

---

## 15. Linting & style — strict golangci-lint v2

`gofumpt` formats; **golangci-lint v2** with `govet`, `staticcheck`, `errcheck`, `errorlint`,
`bodyclose`, `gosec`, **nilaway**, **exhaustruct**, **exhaustive**, **gochecksumtype**, **depguard**,
`gochecknoglobals`, `gocognit`, `revive`, `gocritic`. Zero issues is a gate. NilAway runs via a
`custom-gcl` binary. Fix the code, don't disable; `//nolint` needs a reason; the baseline only
shrinks.

---

## 16. Testing, typing & coverage gates

Blocking: `go build`, `go test -race`, coverage threshold (100% on `internal/*/domain`), **gremlins**
clean on the core, `golangci-lint`, `gosec`, `govulncheck`, `sqlc vet`, `squawk`, and the
OpenAPI conformance + drift gates. Go measures **statement** coverage; the pure functional core makes
100% trivial, and gremlins provides the assertion-strength guarantee branch coverage alone never did.
Layers: domain/app unit tests (no DB/HTTP, the bulk) → adapter tests (Testcontainers Postgres;
`httptest` for external HTTP, no network) → handler/contract tests (ogen server in-process).

## 17. Conventions for agents + Definition of Done

**Recipe — add a feature:** goose migration (constraints DB-level; `squawk` passes) → `db/
queries/*.sql` + `sqlc generate`/`vet` → domain entity/value object + port → sqlc-backed repository →
use case returning `(T, error)` → add paths to `openapi.yaml`, run §9 gates, `go generate`, implement
the handler → tests (domain 100%, adapter, handler; gremlins on core logic) → regenerate consumers.

**DoD (all blocking):** `go build` + `go test -race` green; coverage met + gremlins clean;
`golangci-lint` clean (incl. nilaway/exhaustive/gochecksumtype/exhaustruct/depguard/gosec);
`gofumpt` + `govulncheck` clean; `sqlc generate` committed + `sqlc vet`; `squawk`;
conformance gates + `go generate` no-diff; union switches exhaustive (no `default` dodge); no N+1;
RFC 9457 errors; `go.sum` committed + supply-chain review; no secrets in the image.

## 19. Modern standards

**19.1 Security.** CORS allow-listed; rate-limit middleware (exempt `/healthz`); strict CSP/HSTS/
nosniff/frame-deny; ogen boundary validation + domain constructors keep illegal inputs out; secrets via
env, never in repo/image.

**19.2 Supply chain.** `go.sum` pins checksums; CI uses `GOFLAGS=-mod=readonly` + `go mod verify`.
**`govulncheck`** is a CI gate (reports only reachable vulns). Minimal deps (prefer stdlib);
Renovate/Dependabot with cooldown; pin GitHub Actions to SHAs; least-privilege CI tokens; optionally
vendor (`-mod=vendor`) for auditable builds.

**19.3 Deployment.** Single static binary (`CGO_ENABLED=0`) → distroless/scratch (or `ko`). Migrations
via goose on boot (the embedded set) or a one-shot job. Postgres-only; no Redis (§20). TLS at a tiny
proxy (Caddy auto-TLS).

**19.4 Observability.** stdlib `log/slog` JSON (method/path/status/duration/request-id); request IDs
into logs + error responses; `/healthz` + `/readyz`; an OTel middleware seam without touching the
domain.

**19.5 API conventions.** Versioned (`/api/v1`), paginated (keyset), cached (ETags). A single mapper
turns typed errors into **RFC 9457 problem+json**, declared in the spec. No business logic in
handlers.

**19.6 DX.** `make dev` runs the binary + a Testcontainers/compose Postgres; lefthook pre-commit
(`gofumpt` + `golangci-lint` + tests on staged packages); CI mirrors §16 in parallel jobs.

---

## 20. Background jobs

Postgres-backed **River** (or goroutines) keeps the "Postgres-only, no Redis" posture. A job is an
inbound adapter that resolves and calls a use case — no business logic of its own; idempotent,
retry-safe; pass IDs, not objects.

---

## 21. Real-time runtime (optional)

Server-authoritative model, and Go makes linearization *structural*: **one goroutine per live session**
owns its state and reads commands off a single channel (single writer, no locks). Clients send intents
over WebSocket (`coder/websocket`); the goroutine validates against the domain, mutates normalized
state + appends a **typed action journal** (no JSONB) in one transaction (`sequence++`), then
**broadcasts role-filtered** updates. Reconnection fetches current role-scoped state over REST — no
replay. **Privileged data is never written** to a channel that shouldn't receive it (a hub test
asserting its absence is a blocking security test). `go test -race` guards shared-state access.
